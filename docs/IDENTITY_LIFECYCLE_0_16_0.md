# Membership and sessions — 0.16.0

Open **Workspace settings** as an owner. Provision member collects name, email, non-owner role, decision note and explicit reviewed confirmation. If an OIDC issuer is configured, an exact subject from the trusted identity administrator is mandatory. Provisioning binds issuer + subject before first sign-in. The API cannot create a user at the external IdP. No invitation or password is emailed, displayed or returned.

Provisioning is author-scoped and idempotent. Recover provisioning retrieves the receipt after an uncertain response. Email uniqueness conflicts do not disclose another tenant. An organization supports at most 200 members and 1,000 provisioning receipts; capacity fails closed. Receipts are excluded from generic workbench results. Automated provisioning-receipt retention is not implemented.

**Local development only:** from the backend directory use your virtual-environment Python with `-m nexus.cli set-local-password --email member@example.com`. The CLI prompts privately twice, requires 12–128 characters, changes only an active account in local mode, revokes its sessions and records an audit event. It also replaces the fragile PowerShell `python -c` password reset sequence used earlier. Never put passwords in command arguments or send them in chat. This command is disabled in pilot mode; pilot members authenticate at the configured IdP.

Owners can change a non-owner's role, activate/deactivate the member or revoke sessions. Roles are engineer, approver, auditor and security; owner promotion/transfer is outside this endpoint. Every change revokes all target sessions and audits its reason. Requests carry a revision bound to identity, role, activation and current session state, so a concurrent sign-in/change forces refresh. Self-access changes and owner targets are protected. Deactivation does not delete business/audit records.

All signed-in users see their active session handles and expiries, with the current session identified. Sign out other sessions requires a reviewed note and preserves the current browser. Session tokens, CSRF values, password hashes and exact IdP bindings are not exposed by the member/session administration endpoints. Device, IP and location histories are not collected and must not be inferred from the labels. The UI shows up to 50 active sessions; revocation applies to all other sessions.

Eight backend tests cover provisioning/recovery/idempotency, roles, stale revisions, offboarding/session invalidation, owner protection, tenant isolation, trusted subject requirements, local-only password setup, session privacy and CSRF. These are disposable local tests; real IdP MFA/login/offboarding acceptance remains open. There is no SCIM/SAML, passkey enrollment, workload federation, owner-transfer approval, invitation delivery or enterprise access certification in this release. This workstream remains partial.
