# Upgrade to 0.16.0

1. Export any UI walkthrough examples you want to retain. Stop API/worker processes and back up your existing source, settings and databases. Keep private `.env`, data and backups.
2. Extract the new ZIP into a review directory. Copy updated source/scripts/requirements into C:\nexus-ai-control while preserving those private files. Do not copy another machine's virtual environment or node_modules. Schema remains 8; this release does not reset accounts or business records. Follow earlier schema-8 instructions if upgrading from an older schema.
3. From PowerShell at C:\nexus-ai-control run `.\scripts\start.cmd`. It installs the added NumPy dependency, builds the console and starts API plus worker. Keep the terminal open and open the newly printed URL. Hard-refresh to load v0.16.0 assets. Use a supported Python with an available NumPy wheel; native Windows/Python 3.14 acceptance has not been performed here.
4. Sign in with your existing owner account. Open Document library and add an authorized synthetic text source; then open Knowledge & RAG. Search for its terms, open the receipt and inspect the citation/version and score breakdown. No external provider key is needed for this local ranking path.
5. Open Workspace settings. Provision a disposable non-owner test member with a reviewed note. In local mode set its password privately using `..\.venv\Scripts\python.exe -m nexus.cli set-local-password --email member@example.com` from the backend directory. Sign in using a separate browser session. Verify role changes/deactivation invalidate that session and retain records. Do not use real staff access for a smoke test.
6. Product UI walkthrough still contains 18 areas/216 function previews. Current full exports use release 0.16; validated 0.15 and legacy 0.14 imports remain supported. Design records never activate missing backend services.
7. Read PRODUCTION_GAPS_0_16_0.md before deployment. Pilot configuration requires reviewed IdP, PostgreSQL, policy, secrets, TLS and external-service acceptance. Do not equate the local successful startup or UI design coverage with production readiness.

Rollback: stop writers, restore matching pre-upgrade source/settings and a verified compatible backup in an isolated destination first. Never delete the database or reset accounts to fix a UI upgrade. New internal receipts reuse schema 8; older generic workbench listings do not know the new private kinds, so evaluate down-version visibility before allowing users into an old build.
