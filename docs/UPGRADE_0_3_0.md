# Upgrade to NEXUS AI Control 0.3.0

This release includes the full application, not just a UI theme. It adds operations readiness, signed cursor audit search, owner-controlled member revocation and expired-record maintenance.

## Existing installation

1. Stop the API and execution worker. Back up both control and synthetic business databases. Keep your private `.env` and signing secrets.
2. Extract the new source into a separate directory. Transfer your existing configuration and data securely; do not overwrite the new frontend source with old files.
3. Install `backend/requirements.txt` in the application virtual environment. Build the UI from `frontend` with `npm ci` and `npm run build` if rebuilding; compiled assets are included.
4. From `backend`, run `python -m nexus.cli migrate`. Schema version stays at **2**. The existing 0.1-to-0.2 migration is included for older installations.
5. Start the API and worker using README instructions. `/health/live` reports 0.3.0; `/health/ready` reports schema 2. Check your sign-in and action workflow.

No password reset, schema drop or data deletion is required for this upgrade. A rollback must preserve the same configuration and data; review access changes before running earlier source.

## New operations

- Audit explorer searches all matching audit events before applying its page boundary. The UI loads 25 events at a time. Cursors last 15 minutes and are bound to the organization and trimmed search text. Restart a search if its cursor expires.
- Owners can revoke non-owner members in Settings. A reason is required. Revocation disables future local/SSO login and removes existing local sessions in one database transaction. Users cannot revoke themselves; owner accounts are protected. Use a reviewed ownership-transfer procedure for owner changes.
- Member revocation does not automatically contain owned agents or offboard an external IdP. Review active agents and use their containment action separately.
- Operations readiness reports configuration and expired session/export counts for the signed-in organization. It is not a live external-service health probe or a security certification.

## Maintenance

Run from `backend` with the existing environment and virtual environment Python:

```bash
python -m nexus.cli maintenance
python -m nexus.cli maintenance --apply
```

The first command is a dry run. The second deletes expired sessions, expired export snapshots, and OIDC transactions whose expiration is at least one hour old. It never deletes audit events, action records, approvals, users or mock business effects. Counts apply to the configured database across organizations, so only an authorized operator should run it. Expired exports cannot be downloaded before or after cleanup.

Schedule the apply command using your deployment's reviewed job scheduler or OS scheduler. Keep the environment file private, capture the JSON result and alert on nonzero exit. Scheduling is not enabled automatically. Apply only after reviewing your retention and incident requirements. This is operational cleanup, not a legal retention policy or backup solution.

## Preview versus application

The live hosted preview is a read-only UI with synthetic snapshots and simulated sign-in. It never calls your business APIs. Its standalone source is included under `demo-preview/`. The real application remains in `frontend/` and `backend/` with server authentication and governed execution.

Never use demo-preview as an enterprise authentication service. The demo email/password are placeholders, are ignored by the preview, and are not credentials for the installed application. Actual local passwords are generated by `python -m nexus.cli init`.
