# Validate local ranking responses before saving search receipts

Hybrid-search completion now normalizes the ranking process response before reading its error or score fields. A null/non-object response previously raised during completion, producing a server error and leaving the receipt processing until existing interruption handling ran. The regression reproduces that failure; completion now saves a failed `RANKING_FAILED` receipt with no hits so subsequent searches can use the available capacity.

A success response must be an object containing an integer rank from 0 to 32, an integer vocabulary size from 0 to 1,024 and a score list no longer than the requested top-k. Each score must contain exactly a distinct, in-range chunk position plus numeric combined, semantic and lexical scores. Scores must be finite values from 0 through 1; booleans, strings, infinities, NaN and overflowing numeric values are rejected. Chunk positions refer only to the server's previously authorized corpus metadata. Worker-supplied source IDs, excerpts, extra fields or malformed containers are not accepted. Valid scores are copied without rerounding or changing their order.

Known process failures (`SEARCH_TIMEOUT`, `RANKING_FAILED`, `VOCABULARY_LIMIT`, `CORPUS_LIMIT`) keep their codes while accompanying payloads are discarded. Unknown error values become the fixed `RANKING_FAILED` code rather than entering API results, persisted receipts or audit details. This validates protocol shape and bounds; it does not certify relevance or calibrated confidence.

Existing completion ordering, fresh identity/CSRF checks, source-version/access checks and interrupted-receipt handling remain. A changed source still produces `SOURCE_SCOPE_CHANGED` even when the worker response is malformed. Failed receipts retain normal idempotency: replay and recovery acknowledge the original result without computing again; a new intentional search uses a new key. Failures do not count as processing searches, but still count toward existing history/rate limits. No automatic rerun is added.

There is no migration, endpoint, public request field, dependency, frontend change, algorithm or timeout change. Current local LSA/BM25 results and the 36-check synthetic knowledge exercise retain their behavior. Neural retrieval, customer relevance acceptance and production readiness remain separate work.
