# Working adapter, recovery and clearer interfaces — 0.12.0

17 November 2026 | Schema 7 retained | Full production acceptance: not granted.

## Implemented source

**Readable UI.** A light workspace is now the default, retaining the navy sidebar, cyan branding and relevant agent imagery. The appearance toggle preserves a dark option. Default body text is 16px, supporting labels are at least 14px in the revised readability layer, and large mode uses 18px body/16px supporting text. Form controls and primary actions use at least 46px height in the revised workspace layer. Sign-in has a white form panel, dark labels/hints, readable password controls and clearer headings. Cards, metric labels, table headings, pagination, function-map summaries and studio surfaces were adjusted together. Appearance is a local display preference and never changes permissions. Broad design patterns remain shared across the 216-function design inventory; this is not certification of every future screen/state.

Runtime operations and retrieval tools now load as separate chunks. The normal application entry bundle remains below the 500 kB build advisory threshold; the larger synthetic fixture harness may still show an advisory. No extra runtime dependency was added.

**Governed HTTPS business adapter.** The server can now select either its existing synthetic connector or an operator-configured NEXUS Business v1 HTTP adapter. Synthetic mode remains the default. The HTTP implementation supports governed supplier reads, purchase-request creation and authoritative operation lookup. A customer compatibility gateway/service must implement contracts/nexus-business-v1.openapi.json; this is not a universal adapter for arbitrary ERP APIs or MCP servers.

Only a fixed configured HTTPS host/base path is used. Request-supplied destinations, URL credentials, query strings and redirects are rejected. TLS verification stays enabled, with an optional enterprise CA bundle. Environment proxy inheritance is disabled. Credentials are injected through a named server environment variable, never entered or returned by the dashboard. The deployment operator must enforce egress policy and approve the remote host/tenant/credential scope.

Every action envelope binds the configured adapter destination and remote tenant. Durable workflow definitions also pin their destination before review. A destination change blocks queued action dispatch and unsubmitted workflow steps rather than silently moving an approval to another system. Credential rotation alone does not change the binding. Existing linked effects remain evidence to reconcile; changing configuration cannot undo them. Old workflows without a binding retain the original synthetic default.

Requests carry the local operation ID as an idempotency header, plus remote tenant and local organization headers. Customer responses must match operation, organization and tenant; only bounded permitted result fields are retained. The worker verifies supplier, amount, currency, purchase purpose and terminal state. The customer service must independently authorize the credential/organization and atomically deduplicate immutable requests. Client headers cannot establish those customer-side guarantees by themselves.

No HTTP operation is automatically retried. Timeout, non-authoritative status/JSON, oversized response, transport failure or response-scope mismatch conservatively leaves an unknown outcome. Reconciliation performs an authoritative GET only; a 404 does not prove that no prior effect occurred. Local fault injection is disabled for HTTP actions. Configured HTTP mode displays an explicit external-effects banner and accepts bounded customer supplier references. Customer-mode supplier/amount/purpose fields start empty rather than reusing synthetic purchase defaults. The tools endpoint publishes the current fixed server validation schema, including the backwards-compatible supplier-reference expansion. Existing accounts, grants, policies and schema-7 records are preserved.

**Operating signals and metrics.** Release readiness → Runtime signals now includes actual tenant-scoped database counts for actions, agent runs, source documents, unexpired approvals and oldest queued-action age. It displays the current business binding and configured adapter mode without secrets. An optional /metrics endpoint emits fixed-label, aggregate Prometheus-format database gauges. It is disabled unless a separate 32+ character server token is configured; authentication requires the X-Nexus-Metrics-Token header, never a query parameter. Labels contain no tenant names, record IDs or query text. These gauges are snapshots, not worker heartbeats, distributed HTTP metrics, notifications, SLO verification or alert drills.

**Encrypted backups and isolated inspection.** The operator CLI can create a bounded AES-256-GCM archive after writers are stopped and a separate 32-byte base64 encryption key is provisioned. Nonces are random; the key is not stored in the archive. Existing outputs are never overwritten. Encryption uses streaming bounded files, with a 512 MiB archive limit. The normal backup path now closes SQLite snapshot/inspection connections explicitly, avoiding leaked handles and stray WAL sidecars in completed snapshots.

Inspection authenticates the full encrypted archive before extracting only approved regular member files into a temporary directory, verifies its manifest/checksums and SQLite integrity, and never writes to active application data. Wrong keys, tampering and truncated archives are rejected. Backup creation/inspection uses private temporary directories; plaintext temporary files are cleaned on normal completion/failure, not guaranteed securely erased or removed after a machine crash. Use a protected encrypted filesystem and appropriate Windows ACLs. Key custody/rotation, scheduled execution, off-host retention, PostgreSQL restore/failover and measured RPO/RTO remain operator/deployment work. The command requires an explicit quiescence acknowledgement; it cannot independently prove all writers are stopped.

## Verification

Backend: **270 tests: 255 passed, 15 skipped, zero failures/errors**. Frontend: **34 passed**. Skips require PostgreSQL (6), Keycloak (6) or OPA (3). Tests cover adapter request/scope contracts, no automatic retry, destination changes, unknown-outcome reconciliation, strict result verification, current advertised tool schema, scoped signals, metrics authentication, encrypted archive round-trip, overwrite prevention and tamper/wrong-key/truncation rejection. Existing approval, workflow, document ACL, citation and retrieval regression tests remain green. HTTP tests use a controlled in-memory transport; no customer endpoint or financial action was executed.

Browser review used an isolated synthetic harness: overview, function map, studio, document library, light/dark switching, sign-in and actual backend-generated runtime-signal fixtures. Sampled labels were inspected for rendered color/size and corrected; this was not a full automated WCAG audit. The 1363px desktop viewport had no document-level horizontal overflow. The sign-in harness has no real account/session and rejects runtime mutations. Native Windows, full mobile/device matrix, screen readers, live customer integration, deployment penetration/load/soak and full restore acceptance were not certified.
