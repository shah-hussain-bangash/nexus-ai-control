# UI-first product baseline — 0.14.0

18 November 2026 | Schema 8 retained | Full production acceptance: not granted.

## Delivered UI

The new Product UI walkthrough connects the full agreed 18-area, 216-function catalog. Every function has shared list/configuration/review/activity/access/API-handoff views, domain controls, role/step guidance and eight selectable screen states. Six cross-module journeys connect onboarding, agent execution, reviewed knowledge, incident recovery, release review and AI cost control. A review inbox joins the configuration/submission/reviewer/evidence journey. UI coverage search and a five-phase board expose every catalog function; a JSON export preserves a review handoff. Direct function links are supported. No screens are pre-marked accepted.

Forms validate catalog field types/bounds, confirmation pins a revision and requires scope/effect acknowledgements plus a note, and the UI transition model separates Operator submission from Reviewer decisions and Auditor inspection. Stale/denied/unavailable states block changes; uncertain outcomes use reconciliation rather than blind replay. Unsaved examples have a discard/navigation guard. Readable light/dark styling, visible focus, native dialogs and responsive layouts are integrated. An observed hero contrast issue and dark outline-button contrast issue were corrected during browser QA.

All functions use reusable screen templates. This baseline is complete against the agreed inventory, not a claim that every possible enterprise requirement or bespoke visual editor exists. Arabic translation/RTL, full device coverage and formal accessibility acceptance remain future implementation/review work. Review notes/examples exist only in the mounted walkthrough session; export before leaving. There is no import/restore of that walkthrough export in this release. The existing design studio retains its separate server-persisted versioned plan workflow.

## Working source retained

The existing authenticated backend, governance/approvals, bounded durable execution, reviewed PDF/DOCX/OCR intake, scoped text retrieval/citations, document lifecycle, fixed-contract HTTPS business adapter, runtime signals/protected metrics and encrypted backup inspection remain available. The new walkthrough does not invoke planned service routes or change actual identities, permissions, environments, customer systems or infrastructure. Existing implemented workspaces are linked explicitly. No live deployment was changed.

## Verification

Frontend: **41 tests passed**, including all 216 examples' valid/invalid controls, unique phase coverage, all journey targets, persona separation, version checks, negative states, event history and uncertain-outcome reconciliation. Production and synthetic-preview builds passed. Backend regression: **283 tests, 268 passed, 15 skipped, zero failures/errors**; external PostgreSQL (6), Keycloak (6) and OPA (3) checks remain unconfigured. Schema remains 8.

Browser QA used the isolated synthetic harness: full 216-row coverage/search, journey navigation, configuration/validation, discard protection, Operator → inbox → Reviewer → evidence, access-denied display, phase board, export and sampled light/dark text. Export contained 18 modules and 216 functions with backend_activated=false. A 1363px desktop viewport showed no document-level horizontal overflow. All 216 × 8 states were not manually reviewed, and no formal mobile/screen-reader/WCAG/native-Windows/security/load/restore acceptance was performed.
