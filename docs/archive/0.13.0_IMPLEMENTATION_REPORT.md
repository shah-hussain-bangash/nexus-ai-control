# Reviewed document intake and production progress — 0.13.0

17 November 2026 | Additive schema 8 | Full production acceptance: not granted.

## Working changes

The document library now has a persistent, API-backed file intake queue for PDF/DOCX/PNG/JPEG. PDF native text extraction and DOCX main-body extraction run in a separate process. Configured Tesseract enables image and scanned-PDF OCR. Extracted evidence remains private until an authorized operator compares it with the original, supplies a review note and explicitly attests before publishing. Publication creates a scoped existing KnowledgeDocument, chunks it transactionally and enables authorized lexical search/citations. Original file hash, byte count, filename and extraction method remain linked to the published version.

The dashboard exposes queue status, method/pages, extracted-text review, reader roles, original fingerprint, review deadline, retry/cancel/archive controls and uncertain-request recovery. Version-pinned confirmation dialogs, required publication attestation, loading/error/empty states and light/dark/large-text styling are integrated with the working document library. Current function-map links distinguish these runtime paths from long-term design plans. Existing direct UTF-8 upload, replacement, ACL changes, deletion and retrieval regression checks remain available.

The pipeline bounds original files to 1 MiB, PDF length to 12 pages, images to 8 million pixels and extracted UTF-8 text to 32 KiB. Jobs have 3 explicit attempts, a 24-hour review window, scoped idempotency receipts and leased processing. Cancellation/expiry fence late parser output. Author membership/permission is checked before work/publication. Interrupted work becomes an explicit failure. Parser processes receive no NEXUS credentials and have a wall timeout; POSIX memory/CPU/file limits are included. This is not a malware scanner or complete OS sandbox. Windows deployment memory/resource controls remain operator acceptance work.

Original upload bytes and pending text are logically cleared at publication/cancellation/archive and expiry processing. Worker downtime delays physical cleanup; expired publication remains blocked. Published source text and backup retention remain separate. Archive does not delete a published document or reset lifetime receipt capacity. See the intake guide for exact capacity and retention limits.

The previous release's operator-configured HTTPS business contract, destination-bound governed operations, unknown-outcome reconciliation, tenant-scoped runtime signals, protected aggregate metrics and encrypted backup/inspection remain available. Those paths still require customer/identity/cloud/monitoring and recovery acceptance. See archived 0.12 report for detailed scope.

The 216 function definitions are a long-term UI inventory, not 216 live services or a completion percentage.
