# Request-size rejection events

Requests rejected by size validation now produce one `http.request` event through the existing `nexus.http` logger. Previously early returns sent HTTP 400/413 but bypassed the event emitted around application dispatch. Declared-length validation moves from the outer header middleware into the same request control as streamed body validation. Invalid or oversized declared lengths are still rejected before receiving any body. Normal dispatched requests and downstream failures retain their existing event shape and behavior.

The rejection event contains only `event`, a server-generated `request_id`, HTTP `method`, `route`, `status` and `duration_ms`. Its status is 413 for oversized input or 400 for invalid declared length, and its ID matches the error response's `X-Request-ID`; a client-supplied ID is not echoed. Rejection happens before application routing, so the usual route value is `unmatched`. Dispatched requests retain their server route template. Bodies, headers, cookies, authorization values, query strings and raw URL paths are not added to these events. Error response shape and body-size allowances are unchanged, including the larger POST ingestion allowance. The existing outer response middleware now applies its security/cache headers to declared-length errors as it already did for streamed body-size errors.

The event is emitted after the rejection response attempt, including when sending that response raises. It records the size gate's selected status, not proof that the client received the response. It does not dispatch the rejected request into the application. Existing disconnect-before-dispatch behavior is unchanged; these events are not a comprehensive connection-lifecycle or delivery log.

Tests use disposable ASGI scopes and the fixture API to cover chunked and single-message oversized inputs, allowed boundary bodies, the ingestion allowance, correlation, one event per handled request, safe route templates, downstream exceptions and send failure. Submitted private sentinels must stay out of the event. These are local structured events, not external collection, alert delivery, distributed metrics, SLO acceptance or immutable audit evidence. No external logging destination is configured by this change.
