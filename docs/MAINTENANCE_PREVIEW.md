# Maintenance preview and explicit cleanup

`python -m nexus.cli maintenance` previews expired-record counts. Add `--apply` only when your operator workflow intends to delete the eligible sessions, OIDC transactions and exports. Audit evidence is never a cleanup target. The existing OIDC grace period and report fields remain unchanged.

Both forms validate the configured application settings and require an existing database at this release's current schema. They never initialize a workspace, create missing SQLite parent directories, seed accounts or run migrations. An older, newer, uninitialized or unavailable database fails instead of silently upgrading it. Review and execute schema upgrades separately through the established backup/migration process.

SQLite maintenance accepts plain `sqlite`/`sqlite+pysqlite` file URLs without query options. It rejects in-memory databases and missing files. Preview uses `mode=ro`; explicit cleanup uses `mode=rw`, which also refuses to create a file if it disappears after the preflight check. Foreign-key enforcement remains on, including expiration of session runtime contexts through their session cascade. Maintenance does not change journal mode. PostgreSQL preview transactions use `SET TRANSACTION READ ONLY`; cleanup uses a normal transaction against the configured database/search path.

The preview cannot commit data changes through its maintenance connections. Explicit cleanup is one transaction: a failure while executing the deletes rolls back earlier deletes. Database errors return a fixed message without SQL, connection credentials or private driver details. A connection failure during commit can leave the remote outcome uncertain; review database state before retrying. The current-schema marker is checked before cleanup, but is not a full physical schema or database integrity certification. Missing required tables still fail the operation. Protect configured paths and credentials; the guard does not pin paths against replacement or coordinate deployment maintenance with concurrent writers.

Tests use only disposable SQLite databases and the existing opted-in PostgreSQL CI fixture. They exercise read-only enforcement, preview preservation, explicit cleanup/cascades, schema refusal, missing inputs, source disappearance, CLI routing and rollback after an intentionally missing target table. No maintenance preview or deletion is run against the user's active workspace while implementing or validating this change. This adds no scheduled cleanup, audit retention deletion or deployment acceptance claim.
