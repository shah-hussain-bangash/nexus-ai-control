# Streaming backup checksums

Backup creation and inspection calculate SHA-256 in chunks of at most 64 KiB instead of loading an entire database payload into Python memory. Creation records the checksum and byte count from the same open file. Inspection compares both against the existing manifest declarations. Manifest shape, digest algorithm and response fields remain unchanged, so existing valid backups continue to use the same format.

The checksum reader captures the opened file's size, reads no more than that size plus one byte, and rejects a shorter or longer stream. This detects length changes encountered while reading and prevents a growing file from causing unlimited checksum reads. Storage errors use a fixed message without member paths or driver details. Creation failure cannot return success; a partial new plaintext snapshot may remain for private review. Encrypted creation still cleans normal temporary snapshot files and cannot publish an archive before snapshot creation succeeds.

This is a bound on the checksum read buffer, not a benchmark or a limit on total process memory. SQLite integrity checks, tar processing, OS caches and other operations have their own resource use. The encrypted archive limit remains 512 MiB; plaintext backups do not gain a new payload size limit. Tests cover exact digests and sizes around the chunk boundary, a multi-megabyte SQLite snapshot through creation and inspection, length changes, private storage errors and mismatched manifests. PostgreSQL-shaped unit payloads test checksum metadata only; real PostgreSQL restore is exercised separately in CI.

Inputs must still be quiesced and protected. This reader does not freeze file contents, pin a path against replacement, detect every same-length rewrite or changes after the final read, or establish cross-database consistency. Inspection still performs the existing manifest, SQLite integrity and declared foreign-key checks. Application recovery, customer acceptance and measured RPO/RTO remain separate work. All regression fixtures are disposable and use no active operator database or backup.
